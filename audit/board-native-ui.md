# Исправление несоответствия Cockpit Engine

15.10.2026. Основание: пользователь сообщил, что S1 радикально не соответствует выверенному дизайну и механикам движка. Это корректная претензия к интеграции: формальное подключение wheel не означало использование штатных компонентов.

Причина в portable adapter0.2.0a1 общего пакета: вместо native report-shell/page-shell/sheet/rail был создан отдельный `.ce-board` layout; вместо интерактивных таблиц использовался flat-table, хотя table-engine.js загружался. Предыдущие проверки покрывали данные, HTTP, ресурсы и чистые форматтеры, но не поведение интегрированных компонентов. Срез оставался открытым; жалоба запускает стабилизацию этого шва.

Исправление выполнено в существующей изолированной ветке движка `codex/portable-board-s1`, без правок master, MP Cockpit или production. Выпущен новый локальный immutable wheel0.2.0a2, подключён точной версией в Job Seeker. Старый wheel сохранён. Consumer не получает копии CSS/JS и собственного дизайна. Shell использует штатные классы; table adapter вызывает tblHeadCell/tblWrap/tblColgroup/tblEnableSelection. Добавлен общий opt-in tblDispose; старые потребители не переключаются автоматически.

Что восстанавливается: layout листа/rail/типографики, native заголовки и resize, hide/restore, selection и TSV/HTML copy, server sort cycle, сохранение состояния на refresh. В таблице из100 строк CSV-кнопка явно подписана «Скачать страницу»; ложного обещания выгрузить полную45382-row выборку нет. Фильтрация полной выборки остаётся в rail, page-local column filters не включены.

Независимый review (Sol6.1 Low, режим экономии): подтвердил использование настоящих компонентов, выявил предметную подпись в общем runtime и удержание старых таблиц. Подпись нейтрализована, утечка воспроизведена red и устранена tblDispose. Дополнительный DOM-сценарий проверяет refresh→failure→recovery→switch→destroy. Повторного review не проводилось; замечания устранены тестами. Риски невысокой rail, mobile viewport и реальных жестов оставлены для визуальной приёмки.

Проверки:200Python non-DB движка;10 прежних JS;4 новых DOM integration tests на реальных компонентах (jsdom30.1.3), включая настоящий copy. Те же4 сценария проходят по установленным assets wheel,117 package files побайтно совпадают с wheel. [Hash и evidence](board-native-package.json). Board unit34passed. Полный baseline результата дописывается после последнего прогона.

Финальный baseline:1221unit/458deselected (63.03s),87smoke (1.42s), ошибок нет; существующий Starlette/httpx warning сохранён. DB-suite не повторялась: SQL/модель данных не менялись. Итог source200Python/10JS/4DOM и installed4DOM. Обновлённые18767/18768 отвечают200, HTML содержит native shell, все4 ключевых assets побайтно совпадают с установленными и имеют no-cache; [HTTP evidence](board-native-http.json). Это не визуальная проверка. Источник нового wheel — engine commit f87e31b, source ветка сохранена без merge/push.506 baseline target hashes сверены без расхождений.

Процессы18767/18768 обновлены после проверки их command line; worker lifecycle/DB/schema/tunnel configuration не менялись. SQL/report builder не изменялись. Финальные HTTP проверки относятся к запущенной версии, не только source.

Browser снова отклонил обычное чтение уже открытой18768 с сообщением `saved user permission setting`, несмотря на изменение filesystem-профиля. Альтернативные Browser/CDP/headless не использовались. Поэтому **визуальное соответствие исправленной страницы ещё не подтверждено**, S1 не закрывается. jsdom доказывает поведение DOM, а не реальную геометрию/шрифты/viewport.

Минимальное действие для получения новой версии в уже открытой пользовательской вкладке18768 — Ctrl+R; агент не может выполнить reload через заблокированный Browser. Это обновление просмотра, не замена визуальной QA пользователем. Для агентной приёмки требуется разрешённый доступ Browser к этому origin; точное происхождение сохранённого запрета не установлено. После восстановления доступа агент проверяет реальную страницу, состояния, narrow viewport и screenshot без production-данных.

Обратная связь после исправления: пользователь сообщил «Выглядит приемлемо» и поручил проектировать эпик подключения реальных данных. Это положительная пользовательская оценка текущего вида; она не подменяет непройденный агентный interaction/viewport smoke. Новый этап — проектирование эпика, не автоматический допуск к production-доставке. Уже существующее read-only подключение18767 и выполненная SQL parity используются повторно.
