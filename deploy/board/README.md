# GHL.S2 — delivery plan

Поручение пользователя: доставить, визуальная проверка — пользователем. Утверждённые Intent/spec и Global Constraints Greenhouse Live сохраняются; преодоление Browser deny не требуется для пользовательской проверки. Карта — docs/decomposition-map.md.

T1: RED tests/board/test_server.py → server.py с dedicated job_board_reader/passfile; GREEN board suite. Собрать ограниченный tar только board, config/sources.json и закреплённый engine wheel. На lab-do проверить отсутствие конфликтующего board container/role/path; создать роль LOGIN без superuser/createdb/createrole с SELECT только candidate/vacancy/triage_result и default read-only. После применения RWR 0039 роль получает только column-level SELECT на remote_work_readiness_job(vacancy_id,status,value); migration пропускает этот grant, если роль отсутствует, поэтому preflight обязан подтвердить существование роли и post-migration — фактический grant. Секрет генерируется и сохраняется только на сервере. Собрать additive image на известной локальной58МБ базе без сетевых dependencies, bind127.0.0.1:8095, max256МБ/0.5CPU, read-only FS, secret mount, no capabilities. Проверить health, реальный отчёт, права роли, старый worker identity и baseline registry. Проверить rollback start/stop только новой board. Исходная rollback target — отсутствие board; workers/data не откатываются.

T2: подготовить registry addition job-board remote/local8095 health/healthz, проверить parser/port. Сохранить точный registry/desired snapshot. Registry применяется лишь после явного принятия краткого прерывания всех daemon-соединений; без принятия оставить сервер готовым и предложить один конкретный ответ. Не создавать конкурирующий raw SSH tunnel и не менять daemon code/binary. После контролируемого restart восстановить прежние desired=false, проверить всё и HTTP8095. Визуальное качество агент не утверждает. Evidence — audit/greenhouse-board-deploy.md.
