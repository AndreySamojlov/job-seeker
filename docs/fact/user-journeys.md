# User Journeys — FACT

1. Пользователь смотрит локальную панель: агент запускает её; страница читает lab-do и показывает очередь, блокировки, попытки и сервисы. Обновление страницы повторяет чтение. Ошибка SSH/DB отображается как недоступность.
2. Пользователь просит разобраться с заявкой: агент читает applications с application_id, events и artifacts; отделяет записанный статус от проверенного файла/hash и подтверждения отправки. Автоматического повторного submit нет.
3. Пользователь просит восстановить конкретный сервис: агент читает status/health/logs, диагностирует, проверяет image ID и последствия прерывания; применяет ops service при наличии соответствующего задания, проверяет результат. Lifecycle не вызывается для демонстрации.

Полный путь discovery → два способа fill → подтверждённый submit остаётся целью следующих срезов новой сборки. Существующий runtime не отключён.
