# User Journeys — FACT

Область: локальные интерфейсы восстановления и существующий lab-do. Правила функций — [Functional Specification](functional-specification.md), текущее направление — [backlog](../decomposition-map.md).

## Наблюдение и диагностика

Оператор открывает loopback dashboard, запущенный агентом. Видит очередь, блокировки, состояния сервисов и исходы попыток; страница обновляется каждые30 секунд. Локальная OBS.S1 дополнительно различает время чтения источников и последнего зарегистрированного события/полезного результата выбранных типов; состояние обработки без прямого свидетельства остаётся неизвестным. При сетевом сбое независимые блоки сохраняются с пометкой stale до300 секунд либо unavailable; полный отказ предметных данных даёт503 с доступной диагностикой. /healthz не доказывает доступность lab-do. Область применённого кода/процесса — [Observer S1](../../audit/observer-s1.md). Агент читает логи и восстанавливает доступ; пользователь не обязан настраивать SSH.

По просьбе разобрать заявку агент выбирает candidate/application, читает ops views applications/triage/events/artifacts. Сопоставляет текущий статус, историю, наличие/hash файла и proof попытки. Отсутствие доказательства не превращает submitted/unknown в новую отправку.

## Заполнение локальной сборки

После package-ready deterministic fill заполняет сопоставленные поля и прикладывает резюме. Если остались required-поля, состояние agent_fill_pending сохраняет ту же страницу. Агент получает session ID, остаток полей и проверенные значения пакета через fill-worker. Неизвестный факт/согласие не выдумывается; blocker сохраняет условие продолжения.

Done требует текущий session ID и независимую readiness страницы. Устаревший результат/повторный resume отклоняется; потерянная страница восстанавливается через определённый blocked/reopen путь. Cleanup не затрагивает submitting/unknown. Этот сценарий проверен локально; новые worker API ещё не развёрнуты на lab-do.

## Одобрение, отправка и восстановление

Существующие инструменты показывают disclosed summary, создают approval и разрешают submit по TTL/hash и рубильнику. Полная приёмка цепочки после агентного заполнения не завершена: готовность формы не доказывает её соответствие одобренному содержимому. E2.S3 должен закрыть эту границу на synthetic формах до live-допуска.

При просьбе восстановить сервис агент читает status/health/logs, проверяет image ID и риск прерывания, выполняет конкретную разрешённую операцию и проверяет результат. После неизвестного результата команды сначала читает состояние; слепого повтора нет. Production lifecycle проверен fake transport, не тестовым прерыванием здоровых workers.
