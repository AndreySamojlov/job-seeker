# Functional Specification — FACT

На 2026-10-15 реализован код среза A, но эксплуатационная приёмка E1/T2 усилена после недоступности панели: новый Python baseline, изолированные локальные проверки и операционный адаптер существующего lab-do. Полный замысел принадлежит Product Intent и не считается выполненным.

Панель показывает действующие агрегаты вакансий/заявок, блокировки, до 50 готовых заявок, состояния восьми контейнеров и исходы попыток. Недоступность источника возвращает HTTP 503, а не пустую успешную воронку. `/healthz` подтверждает только локальную панель.

CLI/MCP читают вакансии, заявки, triage, метаданные событий, ссылки/наличие/hash артефактов и логи. SQL ограничен whitelist, транзакции read-only. Start/stop/restart адресуют существующий container ID после проверки образа и volume. Явное принятие прерывания обязательно для stop/restart. Реальные lifecycle-изменения не выполнялись при приёмке; проверены fake transport тестами.

Доменный код discovery/triage/resume/package/fill/submit/mail перенесён из фиксированной ревизии. Unit-тесты не доказывают работу полного конвейера с production-схемой. Поздние миграции интегрированы с DB-проверками; агентный путь интегрирован и проверен локально (E2.S2); доказательство связи текущего содержимого формы с одобренным пакетом остаётся E2.S3; существующий runtime продолжает работать в прежнем составе.

При ошибке чтения панель сохраняет в warning этап (summary/blockers/ready/status) и очищенную причину. На transient read отказ выполняется одна повторная попытка, без автоматических повторов lifecycle. Последний успешный HTML хранится в памяти: при сбое выдаётся только в пределах 300 секунд с role=alert, временем и X-Job-Machine-Data:stale; без свежего снимка — 503. Успешное чтение помечено live. Статус контейнеров может быть недоступен отдельно от очереди. После добавления диагностики наблюдались SSH connection timeout и краткая недоступность daemon; исходный старый 503 не восстанавливается задним числом.

E2.S2: deterministic fill передаёт непокрытые required-поля агенту в той же retained-сессии. Агент получает только значения из проверенного пакета. Done проверяет ID сессии, URL и структурную готовность текущей формы; проверка не нажимает Submit и не навигирует. Непроверяемые custom required widgets отклоняются. Доказательство фактов, согласий и содержимого непосредственно перед отправкой остаётся E2.S3. CDP не ограничивается отсутствием метода submit у Python-клиента.
