# Functional Specification — FACT

Область: локальная сборка восстановления `da55881` и операционный доступ к существующему lab-do. Реализованное ниже проверено в разной глубине; статус доказательств — [Test Strategy](test-strategy.md) и [реестр проверок](../../audit/baseline/agent-integration-checks.json). Production использует прежние образы. Ожидаемый полный продукт — [Product Intent](../product-intent.md).

## Возможности и правила

| Возможность | Реализованное поведение | Граница подтверждения |
|---|---|---|
| Сбор вакансий | Discovery нормализует и дедуплицирует источники, verify проверяет доступность и ATS | Код и локальные тесты; полнота всех live-источников не доказана |
| Оценка | Triage хранит оценку и объяснения для кандидата; поиск и eligibility не заменяются новым алгоритмом при переносе | Перенесённое поведение; критерии источников не переопределялись |
| Материалы | Resume/package создают резюме, manifest и раскрытую сводку; ответы locked, неизвестные и политика согласий различимы | Локальная реализация и регрессии; сохранность всей истории относится к E3 |
| Fill | Сначала детерминированное сопоставление и заполнение; нераспознанные required-поля передаются агенту в той же retained-сессии | Оба пути интегрированы локально E2.S2 |
| Agent context | Fill-worker отдаёт ответы из manifest после проверки bytes hash, application ID и payload binding; MCP не читает контейнерный /data на Windows | Новый контракт требует совместимой версии fill-worker; он не развёрнут на production |
| Завершение fill | Done требует актуальный session ID, тот же URL и серверную структурную readiness; stale результат не меняет заявку | Не доказывает соответствие всех DOM-значений одобренному пакету — E2.S3 |
| Approval/submit | Есть одобрение с TTL и payload hash, рубильник, claim/lease, проверка назначения и резюме; попытки и доказательства учитываются отдельно | Общая защита содержимого обоих путей и synthetic E2E ещё не приняты |
| Результат | Подтверждение требует click, confirmation signal, исчезновения формы, отсутствия ошибок и ссылки на screenshot; unknown не разрешает автоматический повтор | Исторический submitted сам по себе не равен доказанной попытке |
| Ответы работодателя | Mail сохраняет входящие сообщения/исходы отдельно от технического состояния отправки | Полная live-доставка почты при восстановлении не проверялась |

## Состояния и восстановление

Основной путь: `needs_package → package_ready → pre_submit_ready → awaiting_approval → approved → submitting → submitted`. Это концептуальный маршрут: некоторые операции обновляют состояние непосредственно SQL; enum/таблица переходов не являются полным runtime-контрактом. Приёмка оценивает фактические store/service и ограничения БД.

Fill может перейти в `agent_fill_pending` либо `fill_blocked`; причины включают неизвестный факт, CAPTCHA/MFA, отсутствие сессии и технический сбой. Done сохраняет страницу; blocked сохраняет ссылку для повторяемой cleanup. Timeout-sweep перепроверяет состояние и сессию под row lock; submitting/submit_unknown не освобождаются им. Повторный resume отклоняется до DOM. Reopen возвращает допустимую заявку в подготовку; старая сессия очищается без перезаписи нового состояния.

Submit хранит `submission_attempt` отдельно: после начала clicking ошибка ведёт в unknown, не в очередь повторного клика. Это инвариант кода, а не утверждение о завершённом E2E-аудите восстановления.

## Наблюдаемость и управление

OBS.S2 заменяет прежние ops-карточки тремя отдельными столбчатыми диаграммами текущих состояний вакансий, заявок и попыток. Каждый график имеет собственную сумму/единицу/максимум шкалы; источники vacancy.state, application.state, submission_attempt.status, охват — все записи summary. Конверсии и периодов нет. NULL/неизвестные состояния не теряются; пустой успех означает отсутствие записей, недоступный summary не порождает нулевые графики. Подробности свежести свернуты, stale/unavailable видимы. [Evidence S2](../../audit/observer-s2.md).

Панель показывает агрегаты вакансий, заявок, блокировок, до 50 готовых заявок, состояния восьми контейнеров и попытки. Локальная OBS.S1 добавляет последнее зарегистрированное событие и последний полезный результат из явно ограниченного набора: discovery/verify вакансии, package-ready и pre-submit-ready. Время события отделено от времени чтения источника и отображается в Europe/Moscow. События не доказывают живую фоновую обработку; её текущее выполнение обозначено неизвестным. failed/refiled, guard-блокировка и submit_unknown не классифицируются как последняя техническая ошибка; общего подтверждённого источника этой ошибки нет.

Исходы пяти блоков независимы: live, stale≤300 секунд, unavailable. Пустой успешный ответ различим с ошибкой чтения. HTTP200/partial сохраняет независимые блоки;200/stale — пригодные снимки без свежих предметных данных;503 — ни один предметный блок недоступен live/stale. Контейнеры при503 всё равно показываются, если доступны. /healthz проверяет только локальный процесс. Доказательства и область поставки — [Observer S1](../../audit/observer-s1.md); остальные возможности Observer ещё открыты.

Ops CLI/MCP предоставляют ограниченные read-only views и логи, start/stop/restart проверенного container ID/image. Stop/restart требуют принятия прерывания; activity=0 не доказывает простой. Live lifecycle-операции не выполнялись в проверках. Условия эксплуатации — [Architecture](architecture.md), пути пользователя — [User Journeys](user-journeys.md).
