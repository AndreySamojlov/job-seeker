# Observer S1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline execution, or superpowers:subagent-driven-development only if the user selects delegation. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Достоверная верхняя сводка существующего lab-do, сохраняющая полезные данные при частичных отказах и отличающая зарегистрированную активность от работающего worker.

**Architecture:** Расширить существующее read-only чтение именованным event-view. Независимые результаты и ограниченные снимки собираются локальным ops dashboard; renderer получает готовую модель и не обращается к БД. Действующий pipeline и production-образы не меняются.

**Tech Stack:** Python 3.12, существующие FastAPI, Psycopg, pytest, uv; Windows PowerShell. Без новых зависимостей и изменения uv.lock.

**Spec:** [Принятый проект, технический контракт OBS.S1](../specs/2026-10-15-job-machine-observer-design.md#технический-контракт-obss1).
**Decomposition:** [OBS.S1.T1–T2](../../decomposition-map.md#принятие-obs-и-проход-obss1--task).
**Status:** План принят, выполнен inline; локальная проверка1177 unit/77 smoke. Исполнительные решения и evidence: audit/observer-s1.md.

## Global Constraints

- «Одна страница, только чтение, существующий lab-do и существующие данные.»
- «Нет управления заданиями, одобрений, отправки, миграций, новых хранилищ, сервисов и инструментирования workers.»
- «Локальная панель не означает доставку новой сборки в production.»
- «Ноль не означает простой.»
- «Raw payload_json и docker logs в сводку не включаются.»
- Существующий tunnel-daemon, только loopback15433/job_machine, default_transaction_read_only=on. Не выводить и не копировать секрет демона.
- DB-тесты только loopback25439/job_machine_recovery_test с проверенным workspace/.runtime/pg-recovery. Live только read-only сверка, без запуска тестов на нём.
- Сохранить пользовательские изменения и исходные checkout. Проверки и доставка выполняются агентом. Здоровые workers не останавливать; процесс панели не заменять без установленной необходимости и принятия прерывания.
- Изолированный рабочий контур выбирать перед исполнением через using-git-worktrees; перенести принятые документы, не теряя незакоммиченные изменения. Порт18766 не занимать вторым процессом.

## Review Focus

1. Более старый конкурентный запрос завершился позже нового — не откатывать снимок и время.
2. Полный отказ БД при доступном Docker — HTTP503 с контейнерными данными, без ложного успеха.
3. Успешный пустой ответ после непустого — очистить старые значения, не продолжать stale.
4. В событии отсутствует timezone либо malformed created_at — не выдумывать время активности.
5. Windows не имеет IANA timezone database — отображать Europe/Moscow без установки новой зависимости, не падать на ZoneInfoNotFoundError.

Каждый пункт покрывается тестами своего Task ниже; это обязательный фокус итогового review.

## Task OBS.S1.T1 — read-only наблюдения

**Consumes:** `query(request: dict) -> tuple[str, tuple]`, `TunnelDashboardClient.data(view, limit=20, **kwargs) -> list[dict]`.

**Produces:** `observations` возвращает 0–2 строки с `kind` (`latest_event`/`latest_result`), `event_id`, `event_type`, `created_at`. Два фиксированных SELECT выбирают последнее событие и последнее событие из whitelist по created_at DESC NULLS LAST, event_id DESC, LIMIT1; NULL timestamps не являются доказанной активностью. SQL не выбирает payload_json. `normalize_observations(rows: list[dict]) -> dict[str, dict | None]` в observations.py возвращает обе kind, отсутствующие как None; невалидный ответ вызывает ValueError. Разрешены ISO8601 строки с timezone или aware datetime; naive/невалидное время не принимается.

## Task OBS.S1.T2 — независимая сводка и снимки

**Consumes:** observations/normalize_observations из T1; существующие summary/blockers/ready и runtime.status.

**Produces:** в dashboard_state.py `BlockResult` dataclass с полями `state: str`, `data: object | None`, `fetched_at: datetime | None`, `error: str | None`; state live/stale/unavailable, пустые данные — live. `SnapshotStore.read(name: str, loader: Callable[[], object]) -> BlockResult`: monotonic TTL300, UTC fetched_at, thread lock, последовательный generation для предотвращения старой записи. `page_outcome(blocks: dict[str, BlockResult]) -> tuple[int, str]`.

В observer_render.py `render_observer_status(blocks: dict[str, BlockResult]) -> str`: чистый HTML верхней сводки. Нормализованные observations помещаются в data соответствующего блока. Даты показываются как UTC+03:00 (Europe/Moscow); использовать datetime.timezone(timedelta(hours=3), name='Europe/Moscow'), так как текущее отображение московского времени не требует исторического пересчёта или tzdata.

- [x] Написать state tests: `test_ttl_boundary_300_and_expiry`, `test_failure_does_not_extend_ttl`, `test_empty_success_replaces_previous_data`, `test_older_completion_cannot_replace_newer_snapshot`. Использовать управляемые monotonic/wall clocks и threading.Event, без реальных ожиданий300сек. При t=300 допустим stale, t>300 unavailable. Проверить независимость нескольких имён блоков.
- [x] Написать HTTP tests для отказа каждого из summary/blockers/ready/observations/status; даже при первом отказе остальные loaders вызываются. Сохранить одно повторение TransientTransportError, постоянные ошибки не повторять. Каждый запрос имеет независимые исходы; блокировки снимков не держатся во время IO.
- [x] Проверить точную outcome-матрицу: нет предметных live/stale →503/unavailable; предметные только stale →200/stale; есть предметный live, но хоть один из пяти блоков не live →200/partial; все пять live →200/live. ## Команды и критерии проверки

Из корня выбранного изолированного checkout:

```powershell
uv sync --frozen --all-groups --python 3.12
.venv\Scripts\python.exe scripts/check_baseline.py smoke
.venv\Scripts\python.exe scripts/check_baseline.py unit
git diff --check
```

smoke уже включает tests/ops, поэтому новые проверки попадают в существующий безопасный runner без его изменения. PASS — exit0 и подтверждённые counts без пропуска новых тестов. Red — ожидаемые failures новых требований, не ошибка окружения. Не обходить отказ runner из-за .env/live-конфигурации прямым pytest. SQL-семантика проверяется read-only сверкой и при необходимости изолированной DB-проверкой, mocks не считаются доказательством исполнения PostgreSQL.

## Самопроверка и передача

Покрытие S1: источники/времена/ошибки → T1; independent failures/cache/render/HTTP → T2. Все пять Review Focus имеют проверки. S2–S4, исправление historical data, доставка production и реальные отправки исключены. Новых продуктовых решений не добавлено.

Рекомендуемый способ исполнения — inline в текущем чате: два последовательных Task с общим контрактом, затем независимый итоговый review доступным инструментом code review. Делегация — только если пользователь её выберет. Перед реализацией требуется рассмотрение этого плана и выбор способа исполнения согласно Writing Plans; текущий документ не означает начало исполнения.
